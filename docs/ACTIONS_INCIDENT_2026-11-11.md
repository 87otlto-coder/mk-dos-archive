# GitHub Actions storage incident and Windows-only CI policy (2026-11-11)

## What happened
On 11 November 2026, an audit of `87otlto-coder/mk-dos-archive` found 316 retained Actions artifacts (~4,722.03 MiB), including 226 `mk-dos-p11-browser-build` uploads (~4,720.46 MiB). These generated ZIPs dominated storage. GitHub Free Actions storage alerts and a $0 spending cap made continued indiscriminate uploads unsustainable. GitHub also experienced a separate Actions service degradation with queued jobs; do not confuse a platform incident with failed project tests or missing permissions.

Across three verified cleanup passes, 223 old browser builds were deleted. The resulting policy retains **the three newest successful browser builds**, and leaves the 38 P77 verification kits, 29 P78 source units and 23 P80 source units (90 protected research artifacts) outside browser cleanup. A live MK dispatch (run [43104204133](https://github.com/87otlto-coder/mk-dos-archive/actions/runs/43104204133)) succeeded; its retention workflow (run [43104365461](https://github.com/87otlto-coder/mk-dos-archive/actions/runs/43104365461)) retained artifact IDs 13892539543, 13804616993 and 13803967997 and removed older ID 13802158644. SpriteMine's post-policy main test run [43103289128](https://github.com/87otlto-coder/SpriteMine/actions/runs/43103289128) passed four jobs; Scummbucket had no Actions workflow on main at the time.

## Why it happened
The old MK workflow uploaded a browser ZIP on routine runs, retained it for 14 days, and did not rotate redundant generated outputs. Earlier cleanup overvalued differing build hashes and milestone provenance even when source commits could reproduce the outputs. A Linux/Windows/Python-version matrix in SpriteMine also ran platform checks that were not needed for the owner's personal Windows-first development goals. Actions outages can independently queue jobs; changing visibility or retrying repeatedly is not a substitute for reading GitHub's incident status and actual job results.

## Mandatory rules for AI agents and CI changes
1. **Windows-only GitHub Actions:** Use `windows-latest` (or an explicitly approved pinned Windows image) for all new and modified jobs. Do not add `ubuntu-*`, `macos-*`, Linux containers, or cross-platform OS matrices unless the owner expressly authorizes an exception. Prefer PowerShell (`pwsh`) and Windows-compatible commands; validate on an actual Windows runner, not just by changing `runs-on`. Do not remove meaningful tests merely to remove Linux.
2. **Avoid unnecessary CI matrices:** Run only supported Windows versions, Python/Node versions, and events with a documented need. Avoid duplicating feature-branch push and PR checks; keep concise smoke and regression coverage. Do not add workflows merely to demonstrate artifact retention.
3. **Browser/build artifacts:** Do not upload disposable generated ZIPs on every routine push. Keep uploads opt-in or strictly justified. After the new upload **and producing run both succeed**, retain only the three newest successful artifacts of the **exact disposable artifact type** across branches, deleting oldest eligible artifacts by verified ID. Serialize cleanup, re-check identity, and use the least GitHub token permissions required; use three-day expiry as a backup. Never delete a good build because a replacement failed.
4. **Protect non-reproducible evidence:** Git commits, decoder scripts, dependency manifests, offsets, checksums, frame/timing observations, provenance, and research verification kits must survive cleanup. Protect MK P77/P78/P80 artifacts explicitly. Distinct generated file hashes or branch names **alone** do not make a browser ZIP irreplaceable. Stop and request approval if recovery of unique evidence cannot be proved.
5. **No game data leakage:** All three original repositories are public. Never commit or upload proprietary ROMs, DOS game files, extracted copyrighted assets, private fixtures, secrets, or local-only captures to commits, PRs, Actions logs, caches, artifacts or release attachments. Inspect git history and output paths before exposing new data. Public visitors may fork or propose changes but must not be granted write rights to the originals. Preserve existing owner-authorized tool access.
6. **Observe and verify:** Before deletion, inventory names, IDs, producing run conclusions, sizes and digests; retain a ledger outside ephemeral artifacts. Verify the after-state and report exact deletions and protected counts. Inspect GitHub Status when runs queue without jobs, and distinguish service outage, billing cap, permissions, CI failure and unsupported tool operations. Do not conceal errors or claim success without evidence.
7. **Treat existing Linux jobs as migration debt, not an exception:** Inspect current workflows before editing. Migrate every existing Ubuntu job safely to Windows with equivalent checks, then run an actual hosted Windows validation before declaring Windows-only CI complete. If a command depends on Linux-specific tools/paths/browser packaging, document the blocker and keep the change unmerged rather than silently break production CI.
8. **Review discipline:** Use a branch and PR for workflow/policy edits, avoid rewriting Git history, do not alter repository visibility or protections without explicit owner approval, and keep CI costs controlled. Maintain the $0 spending budget unless separately authorized.

**Scope:** These rules apply to Scummbucket, SpriteMine and mk-dos-archive and to future work by coding agents. Repository-specific instructions may add stricter evidence safeguards.

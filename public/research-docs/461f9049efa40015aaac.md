# 1. Why this pass exists

The long-term product target remains a fully fledged MK-DOS asset compiler/recompiler, not a palette editor or cheat utility.

Target architecture:

**Binary → structured/lossless IR → editable representation/canvas → compiler → Binary**

Media export such as PNG/GIF is a companion capability. Music and SFX may later enter the same asset model once their formats and runtime relationships are independently qualified.

Pass 1E.3N recovered enough character, palette, progression and Shang Tsung morph semantics to stop open-ended combat archaeology. Pass 1E.3O.1 deliberately pivots toward the animation/composition layer needed by the eventual compiler.

The eight Shang Tsung morph sequences are used as controlled fixtures because 1E.3N.4 already established their target identities, transition palettes, descriptors, generic fighter-palette restoration, and unmorph relationship. They are compact enough to recover animation mechanics without prematurely generalizing the whole engine.

# 4. Animation-stream interpreter ground truth

Relevant exact Watcom symbols recovered from the authentic executable model:

- `DO_NEXT_A9_FRAME` — code segment 1, Watcom offset `0x000194E1`, physical `0x00069F35`
- `MFRAMEW` — code segment 1, Watcom offset `0x00019595`, physical `0x00069FE9`
- `PRCSLP` — code segment 1, Watcom offset `0x0001D576`, physical `0x0006DFCA`
- `FLIP_MULTI` — code segment 1, Watcom offset `0x00019389`
- `MULTI_ADJUST_XY` — code segment 1, Watcom offset `0x00019779`
- `A9` — data segment 2, Watcom offset `0x00024B54`

The command jump table is at Watcom static-data offset:

`0x0000F27C`

Its six handler entries target:

- command 1 → code offset `0x00019517`, physical `0x00069F6B`
- command 2 → code offset `0x00019526`, physical `0x00069F7A`
- command 3 → code offset `0x0001952D`, physical `0x00069F81`
- command 4 → code offset `0x00019546`, physical `0x00069F9A`
- command 5 → code offset `0x00019561`, physical `0x00069FB5`
- command 6 → code offset `0x00019506`, physical `0x00069F5A`

The mechanically qualified grammar is:

| Stream value | Qualified semantic | Parameter | Verified behavior |
|---:|---|---:|---|
| `0` | `END` | none | Returns with ZF set; `MFRAMEW` terminates. |
| `1` | `STREAM_JUMP` | dword | Replaces global `A9` with the following dword and resumes the interpreter. |
| `2` | `FLIP_MULTI` | none | Calls exact symbol `FLIP_MULTI` and continues. |
| `3` | `ADJUST_X` | signed word | Loads X into EAX, clears EBX/Y, calls exact `MULTI_ADJUST_XY`, continues. |
| `4` | `ADJUST_XY` | two signed words | Loads X/Y into EAX/EBX, calls exact `MULTI_ADJUST_XY`, continues. |
| `5` | `SET_FRAME_NO_SLEEP` | dword | Stores following dword into object frame field `+0x40`; returns carry set. |
| `6` | `CALLBACK` | dword | Calls the following dword as code and continues. |
| `>6` | ordinary frame event | value itself | Stores the value into object frame field `+0x40`; carry clear. |

This is substantially more useful than merely knowing command 6 from the Shang palette pass: 1E.3O.1 establishes a bounded command grammar for values 0–6 and the ordinary-frame branch.

# 5. `MFRAMEW` timing semantics

`MFRAMEW` provides the timing/control side of the interpreter.

Verified bounded behavior:

1. caller EAX is retained as a dwell/sleep value;
2. `DO_NEXT_A9_FRAME` consumes the next stream event;
3. ZF indicates stream termination;
4. CF indicates immediate reparsing rather than a sleep;
5. an ordinary frame event restores the saved dwell value and calls exact symbol `PRCSLP`;
6. command 5 sets CF, so `MFRAMEW` immediately consumes the next event without calling `PRCSLP`.

Therefore:

> **The controlled Shang morph streams do not contain an embedded millisecond/frame duration. Their ordinary frame dwell is supplied by the caller of `MFRAMEW`.**

The UI must not invent original timing from the stream. The current panel's cycling speed is editor-only convenience timing and is labelled accordingly.

# 12. Why this matters to the asset compiler

This is the first pass to establish a complete, mechanically supported path from animation semantics to a composed exportable visual:

**animation stream → frame record → descriptor → GRA sprite → palette dependency → aligned canvas**

That is the correct direction for the eventual compiler UI. The editor should ultimately manipulate semantic structures while retaining the binary relationships required for deterministic recompilation.

The current PNG export is intentionally one-way/read-only. It proves that recovered structure is sufficient to reconstruct a useful media representation without weakening the recompiler requirements.

# 13. Strict current boundary

1E.3O.1 does **not** establish:

- that every MK1 frame record is single-part;
- the generic grammar for multi-part frames;
- the complete animation/group format;
- a lossless animation IR round trip;
- a frame/group serializer;
- editable ordering or descriptor-placement write-back;
- original morph dwell timing;
- GIF export using original timing;
- stage animation grammar;
- combat semantics for animation callbacks beyond the commands mechanically qualified here.

Do not expose write-back merely because the controlled morph preview works.

# 16. Recommended next pass

## 1E.3O.2 — Multi-Part Frame / Animation Group Grammar + Lossless IR

The next pass should broaden deliberately from the simple `[descriptor, 0]` morph fixture.

Objectives:

1. find representative animation frame records containing multiple descriptor references before the frame terminator;
2. establish how multi-part composition ordering and coordinates are represented;
3. determine whether frame records contain additional commands/metadata beyond descriptor lists;
4. preserve unknown/raw fields rather than normalizing them away;
5. define a reusable lossless animation IR containing:
   - stream events;
   - command operands;
   - frame records;
   - descriptor references;
   - resource/file provenance;
   - palette dependencies;
   - composition offsets;
   - timing context where independently qualified;
   - raw bytes/unknown fields;
6. prove extraction → no-edit serialization for the bounded animation fixture before exposing write-back;
7. only then consider controlled frame-order/XY editing and broader media export such as GIF.

This keeps the project aimed at the actual end goal: a semantic asset compiler that can both reconstruct useful media and safely recompile supported edits into the original DOS game structures.

## Mechanically qualified animation interpreter

`DO_NEXT_A9_FRAME` (`MKUTIL.ASM`) dispatches stream values as follows:

| Value | Qualified semantic | Operand / effect |
|---|---|---|
| `0` | `END` | returns with the zero flag indicating stream termination |
| `1` | `STREAM_JUMP` | next dword replaces global `A9`; interpreter continues |
| `2` | `FLIP_MULTI` | calls exact symbol `FLIP_MULTI`; interpreter continues |
| `3` | `ADJUST_X` | signed 16-bit X; clears Y/EBX and calls `MULTI_ADJUST_XY` |
| `4` | `ADJUST_XY` | signed 16-bit X and Y; calls `MULTI_ADJUST_XY` |
| `5` | `SET_FRAME_NO_SLEEP` | next dword becomes object frame field `+0x40`; returns carry set |
| `6` | `CALLBACK` | next dword is called as code; interpreter continues |
| `>6` | ordinary frame event | value is stored in object frame field `+0x40`; carry clear |

`MFRAMEW` supplies the timing side of this grammar. The caller's EAX is retained as the dwell/sleep value. After an ordinary frame, `MFRAMEW` calls exact symbol `PRCSLP` with that value and then continues parsing. Command 5 returns carry set, causing immediate reparsing with no `PRCSLP` call. ### LE Page Map Correction & Real-Fixture Validation (Milestone 1E.2A.1)
- **Status**: VERIFIED
- **Problem Statement**:
  - In initial Pass 1E.2A execution on the real MK1 fixture, Object 1 and Object 2 were detected with 0 mapped pages despite 130 module pages in the LE header.
- **Root Cause Analysis**:
  - The Linear Executable (LE) format defines each 4-byte page-map entry as:
    * Byte 0: Physical page number MSB (bits 16..23)
    * Byte 1: Physical page number MID (bits 8..15)
    * Byte 2: Physical page number LSB (bits 0..7)
    * Byte 3: Page flags (0 = valid, 1 = iterated, 2 = invalid, 3 = zero-filled, 4 = range)
  - Formula: `physicalPageNumber = ((b0 * 0x10000) + (b1 * 0x100) + b2)`.
  - The prior parser decoded bytes 0..2 as little-endian `(b0 + (b1 << 8) + (b2 << 16))`. Since `b0` and `b1` are typically 0 for small physical page counts, the decoded page numbers were evaluated as either zero or massive out-of-range values, resulting in zero valid page mappings.
- **Correction Applied**:
  - Implemented generic big-endian 24-bit physical page number decoding across all LE parsing routines without hardcoding or MK1-specific special casing.
  - Corrected LE object flag `0x0100` mapping to `OBJ_PERM_SWAPPABLE` (swappable page capability, not LX zero-fill).
  - Cleaned up target OS validation to standard LE specification values 1..4.
- **Forensic Verification on MK1 Fixture**:
  - Total page-map entries: 130
  - Object 1 (R-X region, 60 pages): Contiguous physical pages mapped starting at file offset `0x0002A400`.
  - Object 2 (Data, 70 pages): 65 contiguous data pages mapped, followed by 5 zero-filled pages (uninitialized BSS / heap / stack).
  - Validation Anchors Preliminary Note:
    * Filename / String Area Base (`0x0008CA54`) is verified within Object 2 (Data).
    * (Note: Kano Descriptors and Graphics Handle Table physical offsets lie in the Post-Module Tail beyond file-backed module pages; see Milestone 1E.2A.2 for detailed boundary hardening and regional topology).
